# PiSonde Mobile 0.3.22

Fixes misleading upstream Wi-Fi status: a selected or authenticating profile no longer appears connected. A connection needs completed activation, IPv4 and a gateway; Internet reachability remains unverified. The Wi-Fi page refreshes cached status without repeatedly forcing scans.

Adds detection for sustained CONN_FAILED authentication failures on a network already observed working during the current broker process: at least three events spanning 60 seconds within a 120-second window. Unknown networks, WRONG_KEY events, ordinary coverage loss and absence of connected phones do not qualify for this new detector.

Persistent faults first use isolated management recovery. If failures continue after five minutes, recovery may reset only the configured Linksys AE6000 USB device. USB recovery is limited to twice per hour and a ten-minute USB cooldown; counters/limits are scoped to the running broker process. Existing startup grace, AP/shared-service limits and update/power interlocks remain. Healthy upstream service clears escalation state.

Reset requires the configured upstream MAC, AE6000 vendor/product IDs, a non-hub USB device and the matching USB character-device number. The helper accepts no target arguments and runs with a 12-second subprocess timeout. Profiles, passwords, local reception history, update trust and the opt-in SDR reboot policy are preserved.

This uses a USB device reset, not USB port power cycling. Physical unplug/replug recovered the field device; recovery via this software reset has not yet been demonstrated on hardware. If it fails, replug the Linksys. No whole-Pi reboot, USB hub reset or SDR reset is added for upstream Wi-Fi faults.

All 254 offline tests pass, including synthetic sysfs/device identity guards, mocked ioctl, status parsing, authentication filtering, cooldowns and update deferral. No hardware reset is executed by tests.
