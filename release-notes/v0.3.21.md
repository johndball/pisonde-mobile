# PiSonde Mobile 0.3.21

Adds Device controls → SDR recovery → Reboot PiSonde if SDR recovery is exhausted. This option defaults off. If enabled, another SDR fault after three targeted USB reset attempts within one hour can schedule a Pi reboot. A persistent cooldown allows at most one automatic recovery reboot per hour, including across boots and policy toggles.

Existing queued/interrupted update and pending-power interlocks block reboot scheduling. A blocked request does not consume the cooldown. Automatic reboot reasons are logged and a queued reboot is shown in receiver status. An absence of decoded packets does not trigger reboot.

The recovery API returns a generic error on failure; exception details remain in the local service log. CSRF and strict boolean validation are retained.

Settings, local reception history, signing trust and existing upload behavior are preserved. DFM/RS41 remain local-only. This is a final recovery option, not a diagnosis or guaranteed fix for the underlying SDR stall. Hardware/browser validation remains separate from offline tests.

All 237 offline regression checks pass.
