# PiSonde Mobile 0.3.23

Adds one plain-text health row directly below the main header: CPU utilization, CPU temperature in Celsius/Fahrenheit, free disk space and percentage, and current power/throttling warnings. Hardware reads run in a five-second background sampler, not inside dashboard requests. Battery charge and USB input voltage display N/A because the standard Pi installation cannot measure them. Missing/stale sensor results are never presented as healthy.

The Wi-Fi page shows each adapter's current IPv4 addresses directly below its runtime MAC/interface. Missing or unplugged interfaces show No IPv4 address. No personal addresses or network identities are included in source.

Closes a recovery blind spot when NetworkManager retains completed activation, IPv4 and gateway information but the local upstream link stops resolving the gateway. The watchdog stimulates local gateway neighbour resolution and inspects ARP state. A blocked ping by itself is ignored. Four FAILED observations spanning at least 90 seconds within 150 seconds qualify only after that same profile/gateway was previously observed REACHABLE in the current broker. STALE, INCOMPLETE, unknown/missing gateway, missing coverage and remote Internet failure do not qualify for this new detector. A failed gateway is not proof of a faulty adapter: gateway/AP outages may also qualify, so recovery stays bounded.

Retains management-first recovery followed by the existing fixed-target AE6000 USB reset, five-minute escalation delay, ten-minute USB cooldown, two USB attempts per hour, update/power interlocks and onboard AP role. A sustained gateway failure does not falsely clear escalation simply because an IP address remains configured. This is device reset, not physical port power cycling; live recovery effectiveness is still unverified. No Wi-Fi-triggered whole-Pi reboot is introduced.

Retains the last 60 fixed recovery/startup records in /var/lib/pisonde-updater/wifi-recovery.json across process and Pi restarts. Records contain timestamps, boot IDs, fixed reasons and counters, not raw journals, credentials, SSIDs or MACs. Live counters and rate limits remain scoped to the broker process; the file is diagnostic history, not persisted cooldown state. It does not identify the cause of abrupt Pi restarts.

Fixes updater support migration failing under the Wi-Fi broker's read-only /etc service namespace. The broker asks systemd to start a fixed dedicated support worker; only that worker writes systemd configuration, keeping ProtectSystem=full on the broker. Scheduled/manual update workers also check support migration. Existing settings, reception history, trust key and optional SDR reboot policy are preserved.

Offline regression tests cover gateway baseline/duration/escalation, blocked ICMP, missing interfaces/IPs, persistent bounded diagnostics, worker routing/interlocks, CPU deltas, temperature/power formatting and stale UI data. No real USB reset, reboot or network change is performed in tests. Field validation remains required.
